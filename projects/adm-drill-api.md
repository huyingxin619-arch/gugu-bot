## 项目背景

### 痛点
当前 ADM/TVM 多维钻取**仅有界面操作，无公开 API**。业务同事想让自有 AI agent 做自动化报告，必须人工导出数据再喂给 agent，无法端到端自动。

已有 API（basic/show、realtime/show、reach/show、sivt/show）是同步即时查询，不支持多维度交叉下钻和异步大查询。

### 目标
把现有纯界面操作的多维钻取 API 化，支持业务 Agent 异步提交 → 排队计算 → 自动报告。

### 核心决策
- 技术已启动开发，预计2周内完成
- PRD 定位为**风险排查清单**（暴露技术易遗漏细节），非技术实施的前置输入
- 古古负责 PRD 框架 + 场景 + 错误码 + 风险清单
- AdMonitor 负责维度/指标映射 + API 设计 + 技术参数回填

## 子需求：TVM多维钻取补SIVT日志异常指标

**背景：** 烟台要数据洞察+多维钻取所有维度指标API化。排查发现数据洞察大部分指标多维钻取已有，唯独TvMonitor的SIVT"日志异常"指标多维钻取里没有。

**"日志异常"定义：** OTT SIVT的"无效ID曝光"规则在TVM界面上的对外叫法
- OTT端回传了移动端专属ID（IMEI/IDFA等）→ 异常
- 只认MAC和AndroidID为合法ID
- 投屏类放宽：回传合法设备ID即可

**方案：** 先在多维钻取界面上补这个指标，后面API开发同步适配

**进度：** 本周开发，下周测试

**7/27 更新：** 回顾上周五与心宇的讨论，确认无效ID已能覆盖日志异常（m2/m5），多维不需要再加日志异常指标。PG定量化版本不加，仅标准版/高阶版SIVT保留。晴晴已完成开发准备测试
