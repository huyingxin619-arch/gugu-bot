## 项目背景

### 痛点
当前 ADM/TVM 多维钻取**仅有界面操作，无公开 API**。业务同事想让自有 AI agent 做自动化报告，必须人工导出数据再喂给 agent，无法端到端自动。

已有 API（basic/show、realtime/show、reach/show、sivt/show）是同步即时查询，不支持多维度交叉下钻和异步大查询。

### 目标
把现有纯界面操作的多维钻取 API 化，支持业务 Agent 异步提交 → 排队计算 → 自动报告。

### 核心决策
- 技术已启动开发，预计2周内完成
- PRD 定位为**风险排查清单**（暴露技术易遗漏细节），非技术实施的前置输入
- 古古负责 PRD 框架 + 场景 + 错误码 + 风险清单
- AdMonitor 负责维度/指标映射 + API 设计 + 技术参数回填

## 风险跟踪

| 风险 | 影响 | 状态 | 备注 |
|------|------|------|------|
| 界面回显不对齐 | API 提交的任务在界面上无法查看/编辑 | 🔴 未确认 | 需技术做双向验证 |
| 权限适配不一致 | 出现安全漏洞或用户体验断裂 | 🔴 未确认 | 需复用现有 show API 权限体系 |
| 指标计算口径偏差 | API 返回值与界面不一致 | 🟡 待确认 | 需确认同一套计算逻辑 |
| 异步队列可靠性 | 大查询超时或丢失 | 🟡 待确认 | 参考 M+ 异步模式 |
| 幂等实现细节 | 参数指纹算法需注意 JSON 字段顺序 | 🟡 待设计 | 需定义 hash 算法 |
| Table 拆分规则 | API 行为与界面不一致 | 🟡 待确认 | 需对齐 Minisite/时间集拆分逻辑 |

> 详细风险清单见 PRD 第14节「技术实施风险清单」
