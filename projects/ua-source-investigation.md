## 关键发现

- **SDK 行为：** 不主动采集 UA，依赖系统网络框架默认带出
- **异常特征：** 芒果 case 中 UA 高频含 Windows NT 等 PC 特征
- **根因推断：** SDK 默认 UA 被强行篡改，但签名校验未检出（王立涛判断）
- **待验证：** rawlog 捞取验证 + 模拟器/程序调用可能性排查

## 7/28 深夜数据分析（古古+adm）

小胡发了 `pc_flagged_9months_hyx.xlsx`（3147条，9个月），和 adm 交叉分析"SDK 流量被判 PC"的异常数据。

### 核心结论

**伪造链路：** 盗用真设备 ID（OAID/IDFV/CAID）→ 构造 SDK 请求 → md 填真设备型号 → UA 填 Windows 浏览器格式 → 批量发监测请求 → 被判为 PC

**8 条独立证据：**
1. ✅ 6 个 OAID 在大盘同时有移动 UA 和 Windows UA（同 ID 双 UA）— 最硬证据
2. ✅ 全零 IDFA 1123 条，IDFV 仅 142 unique，IDFV/CAID/open_udid 严格 1:1 → 142 个虚拟设备身份池
3. ✅ wDev 153 条 + 111.7.100.21-27 连续 IP 段 → 机房机器
4. ✅ fingerprint 527 unique/3147 条，top 指纹 107 次 → 同 IP+UA 反复使用
5. ✅ session 96.2% 单条 → 无真实浏览行为
6. ✅ mzid 全部 unique + uuid_from 100% 是 mzid → 规避去重
7. ✅ 地域 42.6% 集中广东 vs 正常 14.1%
8. ✅ 13.2% mt/smt 负 gap

**关键修正：** device_model 来自请求中 md 字段（非 UA 解析）。95.1% 请求带了 md → 伪造者填了移动设备型号（高仿）；4.9% md 为空 → fallback 到 UA 解析 → Windows UA → wDev（低仿）。

**全零 IDFA 子群体（35.7%）：** 1123 条全是 iOS，142 个 IDFV 严格绑定 device_model + 1-2 个 IP，open_udid 和 CAID 与 IDFV 严格 1:1，大盘正常流量 0 条全零 IDFA。
