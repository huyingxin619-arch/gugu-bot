## 背景

秒针与广电总局（CVB）合作，通过 SDK 方式实现 IPTV 广告监测。

### IPTV vs OTT 监测原理对比

| 维度 | OTT（互联网电视） | IPTV（交互式网络电视） |
|------|-------------------|----------------------|
| 网络环境 | 公网（互联网） | 专网（IP城域网） |
| 对接方式 | C-S（客户端→服务器） | C-S-S（客户端→服务器→服务器） |
| 设备ID | mac | 机顶盒ID |
| 判断地域依据 | 公网IP | 地域码（广协地域码：1156+行政区划代码） |
| 判断曝光发生事件 | 客户端上报监测代码的时间 | 靠媒体回传 nt=__TIME__ |

### IPTV 监测链路

```
IPTV终端 → 媒体广告投放服务器（请求广告）
         ← 返回广告素材+播放指令
         → 播放广告素材，CVB-SDK采集广告数据
         → 向CVB+秒针收数服务器发送监测请求
CVB+秒针收数服务器 → 秒针Hadoop集群（数据清洗、计算）→ 展示报表
```

**关键差异：** OTT是公网环境，秒针直接收数；IPTV是专网环境，需通过CVB-SDK嵌入广告位，数据先到CVB+秒针收数服务器，再搬运到秒针Hadoop集群计算。IPTV的曝光时间靠媒体回传（nt=__TIME__），而非客户端上报时间。

### 监测代码关键字段

| 字段 | 宏参数 | 含义 |
|------|--------|------|
| rfm | __RFM__ | 地域code（1156+行政区划代码，共10位） |
| nt | __TIME__ | 广告实际发生时间（时间戳） |
| ns | __IP__ | 媒体回传的公网IP |
| tr | __REQUESTID__ | 日志唯一标识 |
| z0 | __DEVICEID__ | device id |
| z1a-z1d | __CONFIG1-4__ | 机动配置项 |
| m | - | TvMonitor系统媒体id |

**聚宝盆：** 专网环境的广告联盟，广东有线、江苏有线等均在联盟内。

## 技术架构（SDK采集分析计算）

### 数据流

```
CVB-SDK 采集 → Kafka → 数仓贴源层(ods) → 解析(dwd) → 清洗(dwd_clean) → 按天分析 → 结果文件 → SFTP → 秒针数据库 → 监测系统前端
```
