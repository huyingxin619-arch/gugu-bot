## 背景

秒针 Prebid 服务（尤其 OTT 端）原本不支持 ID/MAC 黑名单查询，原因是人力排期，非技术瓶颈。
目标：构建 MAC 黑名单查询方法论并评估是否上线。

---

## 现有 Prebid 过滤链（顺序）

1. **IP 黑名单**（秒针）
2. **威胁猎人**（第三方）
3. **IEEE 接口**（秒针）

---

## 评分机制

- 分值范围：**-1 ~ 10**
  - `-1` = 不认识（未收录）
  - `1~10` = 有风险，分越高风险等级越高
- 当前客户卡分：**9分**（过滤9分和10分的流量）

## MAC 黑名单插入方案

与 IP 黑名单并列。与 IP 黑名单不同的是，**MAC 黑名单为二元判定**（黑/非黑），不再有具体分数区分。查询时只返回 id 是否在黑名单里。

## 方法论 2.0（2026/7/14 定稿，7/17 会议确认）

### 生产逻辑

**数据base**：OTT 近30天后验大盘数据（滚动时间窗口，每天生产）

**设备ID**：严格限定为 mac 类 ID（m6 开头，如 m6, m6a, m6b...）

**判黑规则（两条取并集）**：

**规则1 — 单SIVT规则触犯比例（X%阈值）**
- 某MAC近30天触犯某个SIVT规则的流量 / 近30天总流量 ≥ X%
- 则记为「命中该规则」
- triggered_rule_cnt ≥ 1 → 判黑
- 后验规则**剔除「新增设备曝光」**

**规则2 — 整体SIVT触犯比例（U%阈值）**
- 某MAC近30天触犯任意SIVT规则的日志量 / total日志量 ≥ U%
- 则直接判黑
- 同样剔除「新增设备曝光」

**最终黑名单 = 规则1判黑 ∪ 规则2判黑**

### 参数选择及理由

| 参数 | 选定值 | 理由 |
|------|--------|------|
| X（单规则阈值）| 0.5 | 0.4 vs 0.5 对前验过滤差异不大，但0.4后验捕获量掉得更多不划算 |
| U（整体规则阈值）| 0.5 | U从0.5降到0.4，前验差异不大但后验差异较大，选对后验影响更大的阈值 |
| 时间窗口 | 30天 | 90天base黑名单从5000w涨到5800w，但过滤率反而从4%掉到3%。拉长窗口分母变大，短期作恶设备被稀释到阈值以下；2月异常数据（春节因素）也放大了90天base量级 |

### 量级

| 阈值组合 | 30天base | 90天base |
|----------|---------|---------|
| X0.5_U0.5 | ~5000w | ~5800w |
| X0.4_U0.5 | ~5600w | ~6600w |

### 前验过滤效果（X0.5, U0.5, 30天）

- only IP：2.7%
- only MAC：3.8%
- IP×MAC 联合：5.5%

### 后验影响（X0.5, U0.5, 30天）

- SIVT v2 下降约1%（主要来自：高危IP ↓0.7%、夜间曝光 ↓0.3%）
- 后验**只跑了total，未跑分媒体**（杜淑仪会上要求补跑）

## 方法论 1.0（已废弃）

### 原生产逻辑（仅规则1，有分数区分）
1. **窗口**：近 30 天滚动 OTT 后验日志
2. **命中判定**：某 UUID 近 30 天触犯某规则的日志占比 ≥ X%（阈值），记为命中该规则
3. **赋分**：
   - triggered_rule_cnt = 0 → 0 分（白）
   - triggered_rule_cnt = 1 → 9 分（黑）
   - triggered_rule_cnt ≥ 2 → 10 分（黑）
   - 无后验历史 → -1 分
4. **当前阈值候选**：0.4（宽松） vs 0.5（严格）

## 测试结果汇总（方法论1.0历史数据，3日均值）

### 核心数据（阈值 0.4 vs 0.5）

| 维度 | 阈值 0.4 | 阈值 0.5 |
|------|---------|---------|
| Only ID 过滤率 | ~5.5% | ~3.8% |
| IP + ID 联合过滤率 | ~7.0% | ~5.6% |
| ID 净新增（剔除 IP overlap） | ~4.3% | ~2.9% |
| 黑名单量级（≥9分）| 1.586亿 | 1.454亿 |

### ID 与 IEEE 重合度分析 ✅ 已完成

| id 分数 | 不被 IEEE 过滤 | 被 IEEE 过滤 | 独立拦截价值 |
|---------|--------------|------------|------------|
| -1（无历史）| 25.23% | 74.77% | — |
| 0（白）| 94.18% | 5.82% | — |
| 9（黑）| 90.61% | 9.39% | ~91% |
| 10（黑）| 69.99% | 30.01% | ~70% |
| **id 黑整体** | **~89%** | **~11%** | **约 89%** |

**结论**：ID 黑名单与 IEEE 重叠极低，约 89% 独立拦截，具有高度独立的过滤价值。

## 关键判断：值不值得上线

### 核心问题 ✅ 已回答
**MAC 黑名单与 IEEE 过滤的重合度如何？**
- ✅ **重合度低**（~11%）→ **有独立增量价值，推进上线**

### 维度 3：对后验 SIVT 的影响 ⚠️ 已量化

| SIVT 口径 | 引入前 | 阈值 0.4 后 | 平均降幅 | 阈值 0.5 后 | 平均降幅 |
|-----------|-------|------------|---------|------------|---------|
| sivt_v1（全部规则）| ~10.6% | ~8.5% | ↓~2.1% | ~9.0% | ↓~1.6% |
| sivt_v2（排除夜间+新增设备）| ~3.1% | ~1.8% | ↓~1.4% | ~2.0% | ↓~1.2% |
| sivt_v3（再排除高危IP）| ~1.2% | ~0.66% | ↓~0.6% | ~0.70% | ↓~0.5% |

#### 各规则命中率变化（按降幅排序）

| 影响评级 | 规则 | 引入前 | 降幅 | 原因 |
|---------|------|-------|------|------|
| 🔴 **高** | 可疑机型曝光 | ~0.24% | ~90% | 违规强历史复发性，ID 精准覆盖 |
| 🔴 **高** | 高危 IP | ~0.14% | ~87% | 同上 |
| 🔴 **高** | byday 多地域异常 | ~0.32% | ~70% | 同上 |
| 🟡 **中** | 操作系统异常 | ~2.0% | ~40% | sivt_v2 降幅主要贡献者 |
| 🟡 **中** | 夜间曝光 | ~4.8% | ~15% | 基数最大，但大量来自正常设备 |
| 🟢 **低** | 连续曝光 | ~0.004% | ~18% | 绝对量极小 |
| 🟢 **低** | 曝光频繁 | ~0.03% | ~10% | — |
| 🟢 **低** | 曝光碰撞 | ~0.53% | ~5% | 与设备历史关联度低 |
| 🟢 **低** | 新增设备曝光 | ~3.1% | ~3% | 天然无历史记录，ID 黑名单无法覆盖 |

> **后验注意：** Prebid 提前过滤的流量从后验 SIVT 监测视角会"消失"。本次研究已做 SIVT 前后对比量化，但上线时仍需设计 A/B 对比方案。
