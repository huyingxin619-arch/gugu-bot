# 周报生成

用于每周生成结构化工作周报。

## 触发条件

- 用户说"写周报""出周报""搞周报""本周总结"等
- 每周五下午主动提醒用户是否需要出周报

## 前置：用户既有指令（必须遵守）

- PG双周会不列周报
- 一次性咨询/内部工具配置不单列，放"其他"
- 临时性排查项目（如达能SIVT）放"其他"，不单列
- 无具体人名（用角色标签）
- 无具体报价/金额数字
- 宝洁类KA客户脱敏，三九等其他客户可正常写

## 流程（必须按顺序）

### 第一步：全面扫描

**必须扫描以下三个来源，缺一不可：**

1. **`projects/overview.md`** — 逐条过所有项目状态，标记本周可能有进展的
2. **本周各天 `memory/YYYY-MM-DD.md`** — 逐天读，提取每个项目本周发生的事件
3. **各项目详细文件 `projects/xxx.md`** — 对本周有标记的项目，读详细文件确认最新状态

**扫描完整性自检（扫描完后回答）：**
- overview.md 里每个进行中的项目，本周有没有进展？没进展的也要确认，不能跳过
- 本周日记里提到的事项，是否都能对应到某个项目？有没有游离的、没归到任何项目的事件？
- 有没有临时性项目/新项目本周才出现的？（如YUM成本核算、IPTV对齐会等）

不凭日报文字和记忆写周报，以项目文件和日记为事实来源。

### 第二步：逐条核实状态

对每条要写的内容问自己：
- 这是"最新事实"还是"我的推断"？
- 讨论阶段 ≠ 结论阶段，不能把"会上讨论的方向"写成"已对齐/已确定"
- 已修复 ≠ 有问题，不能把已修复的bug还列成待解决问题
- 如果不确定当前状态，标注"待确认"而非自行下结论

### 第三步：确定主线项目结构

**主线项目判定标准：** 有持续推进的实质性工作、有明确里程碑或交付节点、是小胡长期投入的核心方向。

**当前主线项目（供参考，每次需根据实际情况核实）：**
1. AI适配建设（含多维钻取API、M+ API、Loop工作区/adm PM助手等子线）
2. 三九天网AI巡检项目
3. ZPSJ智屏视界像素验证
4. IPTV×CVB广告监测
5. ID Landscape
6. YUM项目成本核算与私有化评估

**注意：**
- AI适配建设下的多条线（多维API、M+ API、Loop）是同一大项目下的平行功能，归在一个标题下，不是平行的独立项目
- 主线项目结构每次需跟用户确认，不自行决定
- 新项目可能升级为主线，主线项目也可能降级为"其他"

### 第四步：筛选分类

**单列项目（主线项目有实质进展）：**
- 写清楚本周做了什么、结论是什么
- 无实质进展的主线项目也要列，只写当前状态一行带过

**合到"其他"（不单列）：**
- 一次性技术支持（如广点通代码解释）
- 临时性排查当前阶段不需重点跟进的（如达能SIVT）
- 内部工具配置、机制优化等

**不列：**
- PG双周会（用户既有指令）
- 已收尾项目无新进展的

### 第五步：自检

逐条检查：
1. 进度表述：是定论还是讨论中？有没有夸大？
2. 状态准确性：写的状态是最新事实还是旧信息？已修复的不要还写成有问题
3. 分类判断：一次性事项是不是放"其他"更合适？有没有违反用户既有指令？
4. 脱敏：有没有具体人名？有没有具体金额？

### 第六步：输出草稿

输出给小胡确认，等小胡反馈后再修改或发送。
不自行直接发送周报。

## 输出格式

```
胡映昕本周周报（YYYY-MM-DD ~ YYYY-MM-DD）

一、[主线项目名]
1. [子线1]
- ...

2. [子线2]
- ...

二、[主线项目名]
本周进展：
- ...
当前状态/待解决问题：...

...

[N]、其他
- [事项]：一行带过
```

## 错误案例（2026-08-28踩坑）

1. **进度夸大** — 把会上讨论的方向写成"已对齐" → 实际还要评估算力才能定。讨论阶段≠结论阶段
2. **状态滞后** — 已修复的bug还列成"有问题" → 没核实最新状态
3. **遗忘用户既有指令** — PG双周会列了 → 之前说过不列周报
4. **分类判断不当** — 一次性技术支持单列项目 → 应放"其他"
5. **项目结构错误** — 多维API、M+ API、Loop列成三个平行独立项目 → 实际都是AI适配建设的子线，应归在一个标题下
6. **项目遗漏** — IPTV/CVB、ID Landscape、YUM本周有进展但初版漏了 → 第一步扫描不全面，只关注了高频项目，没逐条过overview和日记
