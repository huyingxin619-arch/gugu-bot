# 错误码列表（errors.md）

本文档列出 PMS 系统中与 OKR 模块相关的所有错误码。

## 响应错误格式

所有错误响应统一格式：
```json
{
  "code": 40901,
  "message": "KR权重合计必须为100%",
  "data": null,
  "timestamp": "2025-07-06 18:00:00"
}
```

判断成功与否只需检查 `code === 20000`。

## 特殊响应结构说明

绝大多数接口返回统一的 `Result<T>` 结构：
```json
{"code": 20000, "message": "success", "data": <T>, "timestamp": "..."}
```

只有一个接口例外：**GET /api/v1/okr/{planDetailId}/comments**（评论列表）直接返回 `PageResult<CommentVO>` 结构，不嵌套在 `Result` 中：
```json
{"code": 20000, "message": "success", "data": {"records": [...], "total": N, "pageNum": 1, "pageSize": 20, "totalPages": M}, "timestamp": "..."}
```
注意请求参数名为 `page`，而响应分页字段名为 `pageNum`。

## 通用错误码

| code | message | 触发场景 |
|------|---------|----------|
| 20000 | 成功（success） | 请求成功 |
| 40001 | 请求参数错误 | 参数校验失败（@Valid 不通过）、参数格式错误、必填字段缺失 |
| 40002 | 参数格式不正确 | JSON 解析失败等 |
| 40003 | 必填参数缺失 | Query 参数或路径参数缺失 |
| 40101 | 未登录/Token 过期/员工工号不存在 | Authorization Header 缺失、Token 过期；登录接口 employeeCode 不存在时也返回此码（EMPLOYEE_NOT_FOUND） |
| 40102 | Token 无效 | Token 被篡改或签名无效；员工已离职无法登录也返回此码（EMPLOYEE_RESIGNED） |
| 40103 | 登录失败，请稍后重试 | 登录时服务异常 |
| 40104 | 密码错误 | 登录密码不正确 |
| 40105 | 企微授权码无效或已过期 | 企微SSO code失效 |
| 40106 | 企微账号未绑定系统员工 | 企微账号未绑定 |
| 40107 | 验证码错误或已过期 | 重置密码验证码错误/过期 |
| 40108 | 验证码发送过于频繁 | 重置密码验证码限流 |
| 40111 | 账号已锁定 | 多次密码错误导致锁定 |
| 40112 | 账号已禁用 | 账号被管理员禁用 |
| 40113 | CAS Token无效或已过期 | CAS统一认证：用户Token无效或已过期 |
| 40114 | CAS账号未绑定系统员工 | CAS统一认证：工号不存在于系统 |
| 50101 | CAS未配置或AccessToken获取失败 | CAS集成配置缺失或DC接口异常 |
| 50102 | 获取CAS用户信息失败 | ML_CAS_GET_USER_INFO接口调用失败 |
| 40301 | 无操作权限 | 多义错误码，常见触发：非直属上级评分挑战度、非对齐方操作、非本人操作（OKR_NOT_OWNER/OKR_NOT_DIRECT_MANAGER）、目标员工不存在（部分场景用 EMPLOYEE_NOT_EXIST=40301，关注/搜索用 40101，以具体 message 为准） |
| 40302 | 角色权限不足 | 角色权限不够 |
| 40401 | 资源不存在 | 通用资源未找到（O/KR/计划明细/对齐记录/员工等不存在时也可能返回此码，message含具体说明） |
| 40901 | KR权重合计必须为100% | 创建/编辑/聚合编辑 O 时 KR 权重之和不是100%，或单条 KR 权重 ≤0 或 >100 |
| 50001 | 系统内部错误 | 未捕获的服务端异常 |
| 50002 | 数据库操作失败 | SQL执行异常 |
| 50003 | 服务暂不可用 | 依赖服务不可用 |

## OKR Core 模块错误码

| code | message | 触发场景 |
|------|---------|----------|
| 40801 | 计划明细不存在 | planDetailId 无效或已被删除 |
| 40802 | 目标不存在 | objectiveId 无效 |
| 40803 | 非本人操作 | 试图编辑/删除他人的 O/KR |
| 40806 | 关键结果不存在 | keyResultId 无效 |
| 40901 | KR权重合计必须为100% | 创建/编辑/聚合编辑 O 时 KR 权重之和不是100% |
| 40904 | 存在对齐数据，请先取消对齐后再删除 | 删除 O/KR 时存在 ACCEPTED 状态的对齐 |
| 40905 | 已存在FT-OKR=Y的记录，请先取消后新增 | 同一 planDetail 下不能有多个 FT-OKR |
| 40907 | 计划明细状态不允许编辑 | planDetail 状态为 COMPLETED 或 INVISIBLE 时执行写操作 |
| 40910 | KR的新增/删除/权重调整必须通过O聚合保存接口(PUT /objectives/{id}/full)操作，不支持单独增删改 | 调用了已禁用的 `POST /objectives/{oid}/key-results`、`DELETE /key-results/{id}`，或在 `PUT /key-results/{id}` 请求体中传入了 `weight` 字段；必须改用聚合接口 |

## OKR 关注模块错误码

> ⚠️ **错误码冲突说明**：`40910` 在不同模块 message 不同：
> - OKR Core 模块：`KR的新增/删除/权重调整必须通过O聚合保存接口`（调用已禁用接口或传weight字段）
> - 关注模块：`关注人数已达上限(20人)`（关注列表超过20人）
>
> 请根据调用的接口路径区分具体含义。

| code | message | 触发场景 |
|------|---------|----------|
| 40909 | 不能关注自己 | 关注目标为自己 |
| 40910 | 关注人数已达上限(20人) | 关注列表满20人（注意：OKR Core模块也使用40910，message不同） |
| 40911 | 已关注该员工 | 重复关注同一人 |

| code | message | 触发场景 |
|------|---------|----------|
| 40807 | 拆解记录不存在 | UPDATE/DELETE 时指定的 id 无效，或已软删除，或不属于当前 KR |
| 40912 | 拆解比例合计不能超过100% | 所有拆解记录的 ratio 之和超过100% |
| 40913 | 同一下属不可重复拆解 | ADD 时该下属已有该 KR 的拆解记录 |
| 40914 | 只能拆解给汇报线上的下属 | ADD 时目标员工不在汇报线下属范围内 |
| 40915 | 指定的计划明细无可见OKR数据或已不可见 | 对齐视图接口 planDetailId 无可见OKR数据 |
| 40917 | 计划明细不属于当前用户 | 对齐视图接口访问他人 planDetailId |

## 错误处理建议

1. **40101/40102**：清除本地缓存 Token，重新调用 `/api/v1/auth/login` 获取新 Token 后重试
2. **40301**：检查当前账号是否有对应操作权限（如挑战度评分需要直属上级账号）
3. **40901**：提交前校验同一 O 下所有 KR 权重合计 = 100%
4. **40903/40908**：前端提示用户对齐已存在或不能对齐自己
5. **40904**：提示用户先联系被对齐方取消对齐才能删除
6. **40907**：提示当前周期已关闭，不可编辑
7. **40001**：检查必填字段是否都传了、枚举值是否在允许范围内
