# L0 基础知识：OKR是什么、怎么写、跟绩效的关系

> 本文件是OKR陪写助手的知识底座。员工问到OKR基础概念时引用本文件内容解答，不主动灌输。

---

## 一、OKR是什么

OKR（Objectives and Key Results，目标与关键结果）是一套**目标管理工具**，帮你想清楚"这段时间我要往哪走"和"怎么衡量走到了"。

- **O（Objective / 目标）**：你想达成什么方向。定性的、有方向感的、描述期望的终态。回答"我们要去哪"。
- **KR（Key Result / 关键结果）**：怎么衡量O达成了。定量的、可衡量的、KR描述里本身就包含数字+单位+目标值。回答"怎么知道到了没有"。

一个好的O通常配2-4个KR。建议每人每周期3-5个O。

### 好例子 vs 坏例子

| | ❌ 不好的写法 | ✅ 好的写法 |
|---|---|---|
| **O** | 完成HR系统上线 | 打造全员可用的HR数字化基础设施，让人事事务从"跑流程"变成"线上自助" |
| **KR1** | 推进系统开发 | 考勤模块上线，覆盖全员2000+人，使用率≥95% |
| **KR2** | 做培训 | 完成3场全员培训，培训后满意度≥4.2/5 |
| **KR3** | 及时处理问题 | 上线后2周内P0故障数=0，用户问题24h响应率≥90% |

核心区别：左边是在列任务清单（我要做什么），右边是在描述结果（做成什么样算成了）。

## 二、什么是好的OKR

### 好O的标准

1. **是方向和终态，不是任务**。"完成XX项目"是任务，"打造XX让用户获得XX价值"是方向
2. **有挑战性**。如果O设完你觉得"躺着都能完成"，那设低了
3. **一个O只讲一件事**。把两件不相关的事混在一个O里，KR一定拆不干净
4. **简洁清晰**。一句话说清楚，不堆砌套话

### 好KR的标准

1. **描述即目标**：KR描述本身包含明确的数字+单位+目标值，不需要额外字段说明。"NPS从30提升到50"、"P0故障数=0"、"覆盖率100%"——读完就知道目标是什么
2. **衡量结果，不是动作**："举办3场活动"是动作，"活动后转化率≥15%"是结果；"完成系统上线"是动作，"上线稳定运行2周无P0故障"是结果
3. **有挑战性**：**0.6-0.7的达成概率才是好KR**。如果你100%完成了所有KR，说明目标设低了，那不是优秀是保守
4. **KR之间MECE**：同一个O下的KR互相独立、合起来覆盖O的核心维度（不重叠、不遗漏）
5. **权重合计=100%**：同一个O下KR权重之和必须是100%，权重反映优先级（核心KR可以40-50%，次要的10-20%），不要平均分配
6. **每个KR有明确的owner**：一个人扛，不能是"委员会"或"团队"

### 执行型KR vs 探索型KR

- **执行型（EXECUTION）**：你知道怎么做、路径清晰，衡量执行结果。大多数KR属于这一类。
- **探索型（EXPLORATION）**：你不确定能不能做成，需要验证假设。适合新方向、新业务的探索。探索型KR的描述里需要说清楚：核心假设是什么、怎么验证、什么信号算成功、什么情况该停止（kill signal）、投入多少资源、什么时候做决策。探索型最长2个月要收口——要么验证通过升级为执行型，要么判定此路不通转向。

### 常见错误（反面清单）

| 错误 | 例子 | 问题 |
|------|------|------|
| O写成任务清单 | "完成Q2交付、做好团队管理" | 这是TODO list不是O |
| KR没有数字 | "提升产品体验" | 无法衡量，读完不知道做到什么程度算成了 |
| KR是动作不是结果 | "举办3场客户活动" | 活动办完了然后呢？对业务有什么影响？ |
| target设100%能完成 | "保持系统稳定运行" | 这是岗位职责不是OKR，OKR要拉伸 |
| 一个O下KR太多（>5个） | 6-7个KR | 说明O没聚焦，拆碎了 |
| 权重平均分配 | 每个KR都是33%或25% | 说明没有优先级判断 |
| current写"进行中" | "正在做" | 必须有实际值，哪怕是0或"0%" |
| 用模糊动词 | "加强""推进""优化""提升" | 这些词没有衡量标准，后面必须跟数字 |

## 三、OKR跟KPI的区别

这是最常被混淆的概念。

| 维度 | OKR | KPI |
|------|-----|-----|
| **本质** | 目标管理工具——我要去哪、怎么到 | 绩效衡量工具——我的岗位职责底线是什么 |
| **目标感** | 拉伸性、挑战性，0.7完成是好的 | 保底性，达成或超过才算合格 |
| **与奖惩关系** | 不直接挂钩奖惩，是自我管理和对齐的工具 | 直接作为绩效考核的输入 |
| **灵活性** | 月度快照，随时可调整方向，鼓励试错 | 周期内相对固定 |
| **数量** | 聚焦，3-5个O，每个O 2-4个KR | 覆盖岗位核心职责 |
| **心态** | "我想达成什么"（进攻） | "我不能没做到什么"（防守） |
| **完成度解读** | 100%完成=设低了，70%是理想状态 | 100%完成=达标 |

**一句话：KPI是"你必须做到的底线"，OKR是"你想跳起来够到的高度"。两者互补，不矛盾。**

### 在明略，OKR和KPI怎么配合？

- **非产研团队**：KPI（底线目标，在北森系统，有T1门槛/T2目标/T3挑战三档）+ OKR（拉伸目标，在CoMark系统），OKR可选
- **产研团队**：KPI + OKR **双必选**（OKR是必选，但KPI内容和数量可根据leader要求简化）
- KPI分数是绩效等级的**建议输入**（100分以下建议C/100+建议B/110+建议A），最终ABC等级由leader综合品鉴+校准会确定
- OKR完成度**不直接挂钩**绩效评分，但会作为leader判断你"目标感、自驱力、拿结果能力"的参考

## 四、OKR跟绩效考核的关系

**核心原则：OKR是目标管理工具，不是绩效考核工具。**

### 明略绩效体系速览

- **考核周期**：年度考核（每年一次）
- **三档等级**：A（杰出，≤20%）/ B（符合预期，≈70%）/ C（待提升，≥10%），强制分布到一级部门
- **考核输入**：KPI分数（建议参考）+ OKR表现（参考）+ 360反馈（参考）+ leader综合品鉴 + 校准会
- **最终判断权**：在直接leader，必须写书面理由；校准会做横向校准，避免松紧不一

### 为什么OKR不直接挂钩绩效？

1. **挂钩了大家就会设保守目标**——如果OKR完成度直接影响奖金和评级，没人敢设有挑战的目标，OKR就退化成了KPI
2. **0.7完成度的探索价值大于100%完成的保底任务**——试错和探索本身就有价值，不能因为"没100%达成"就惩罚
3. **绩效考核看的是综合表现**——包括你的成长、协作、价值观、AI Native程度等，不只是目标达成

### 那OKR有什么用？

1. **对齐**：让你和上级、团队知道彼此在做什么、往哪个方向走
2. **聚焦**：3-5个O帮你排序优先级，不被琐事淹没
3. **自我驱动**：拉伸性目标push你走出舒适区
4. **沟通工具**：1on1时有共同语言，不用每次从头说"我在忙什么"
5. **成长记录**：月度快照留痕，回头看能看到自己的成长轨迹

### 产研团队的FT-OKR特殊机制

产研实行FT（Feature Team）模式：
- FT leader月度给成员打红绿黄标签（对员工不可见），作为年度绩效参考
- 季度集团产品技术委员会评FT项目奖金（入选≤20%的FT）
- FT-OKR表现是委员会评定FT奖金的重要参考，但不直接挂钩个人绩效

## 五、OKR的节奏

- **设定**：年初（或新入职时）设定OKR框架
- **月度快照**：每月初系统自动继承上月OKR，你可以根据进展调整内容和目标值，确认后成为当月快照
- **随时可改**：OKR不是一成不变的，业务变了、方向调了可以随时改。但改之前想清楚——是目标不合理还是执行不到位？
- **Review节奏团队自定**：各团队可以按自己的节奏做周/双周/月度/季度check-in，系统保留每月快照，想看哪个月的状态都可以回溯
- **年度收口**：到第二年1月1日不再复制继承，年度周期结束

## 七、常见问答

**Q：我第一次写OKR，完全不知道从哪开始？**
A：先告诉我你这个周期最想推动的1-2件事，或者你的上级最近在关注什么。我们从一个方向开始聊，不用一次想全。

**Q：O一定要对齐上级的O吗？**
A：常规的O建议对齐，说清楚你的工作怎么贡献到上级目标。探索型的O（新方向验证）可以不对齐，但需要上级认可，且有时间盒限制。

**Q：KR写多少个合适？**
A：每个O建议2-4个KR。太少可能cover不住O，太多说明拆碎了或O太大。

**Q：写完之后能改吗？**
A：可以。OKR不是合同，月度快照时可以调整。但改之前想清楚：是方向变了，还是执行遇到困难想降低目标？

**Q：探索型KR怎么写？**
A：探索型KR关注的不是"做到多少"，而是"验证什么假设"。需要说清：假设是什么、怎么验证、什么信号说明假设成立、什么信号说明此路不通、投入多少资源、什么时候做决策。

**Q：权重怎么分配？**
A：不要平均分配。最核心的KR给40-50%，次要的10-20%。权重反映你对优先级的判断。单个KR权重不低于10%。
