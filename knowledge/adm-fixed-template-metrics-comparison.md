## 二、API对比验证

### API定义的兼容规则（§6.1）

| 规则 | 约束 | 影响by活动 |
|------|------|-----------|
| R1 | total/byday含指标13(Keywords) → spots必须非空 | ❌ by活动无spots，故13不可用 |
| R2 | total/byday含指标316 → spots必须非空 | ❌ by活动无spots，故316不可用 |
| R3 | 选品牌指标14 → 必须同时选终端类型11 | ⚠️ 联动约束 |
| R4 | regionOrient=true → spots必须非空 | by活动默认false，不影响 |
| R5 | total/accumulate/byday含9/10/11/12/14 → spots必须为空 | ✅ by活动无spots，满足条件 |
| R6 | sheetBy="1"(按地域) → dimension不能含6或7 | by活动默认sheetBy="0"，不影响 |

### 结论

API兼容规则下，by活动模式：
- **不可用指标：** 13(Keywords)、316(监测指标)
- **可用指标：** 其余全部（8-12,14, 41-57, 60-70, 81-84, 90-99, 313-315）
- **可用维度：** 1~7全量
- **API与界面一致：** 是（界面在by活动tab下也不展示关键词指标）

| 10(Net) | ✅ | ✅ | 同上 |
| 11(Terminal) | ✅ | ✅ | 同上 |
| 12(Hours) | ✅ | ✅ | 同上 |
| 13(Keywords) | ❌ | ❌ | R1：需spots非空 → 网站模式无spots |
| 14(Brand) | ✅ | ✅ | R5：需spots为空 ✅ |

| 52-57 | ✅ | ✅ | 无限制(需权限) |

| 60-70 | ✅ | ✅ | 无限制 |

| 313-315 | ✅ | ✅ | 无限制 |
| 316 | ❌ | ✅ | R2：需spots非空 → 广告位满足 ✅ |

**维度变化：**

| 维度 | by活动 | by广告位 | 变化原因 |
|------|--------|---------|----------|
| 1-5 | ✅ | ✅ | 无限制 |
| 6(Minisite) | ✅ | ✅ | 无spots相关限制 |

**结论：by广告位指标有明显变化——**

**新增可用（vs by活动）：**

- 316(监测指标及其它)

**变为不可用（vs by活动）：**
- 9(OS/操作系统)
- 10(Net/联网方式)
- 11(Terminal/终端类型)
- 12(Hours/时段)
- 14(Brand/品牌)

**豁免：**
- 8(App) — 唯一不受spots限制的移动端类指标

## 五、待确认项

1. **界面实际行为交叉校验** — 上述分析基于API文档的兼容规则(R1-R6)，需要和界面实际展示对比：
   - by活动tab下，界面是否隐藏13和316？
   - by网站tab下，界面是否隐藏13和316？
   - by广告位tab下，界面是否隐藏9/10/11/12/14？
   - App(8)在by广告位下界面是否确实可见？

2. **指标481~485** — API文档§6.2提到可视度系列还有481-485，但固定模板§8.2指标列表只写了90-95，需确认481-485是否在固定模板也可用

3. **R3联动** — 品牌指标14需同时选终端类型11，但14在by广告位下不可用，11也不可用，所以R3在by广告位下实际不生效

4. **移动端指标自动追加维度** — API文档说"含8-14时服务端自动追加对应维度"，需确认具体追加哪些维度
