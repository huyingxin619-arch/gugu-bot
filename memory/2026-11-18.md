## 每日11点项目进展汇报 cron 失败修复

- 今天 11:00 的 cron job 报 "Agent couldn't generate a response"
- **根因**：job 挂在飞书私聊 session 上，context 膨胀严重。配置的 model 是 glm-5.2，但 glm-5.2 不可用 → gateway fallback 到 glm-5.3。glm-5.3 在超长 context 下跑了 21 分钟（312K input tokens），agent 无法解析出有效回复。error 是 agent 层面的，不是 API 错误，所以不继续 fallback 到下一个模型
- **修复**：sessionTarget 从飞书私聊 session 改成 `isolated`，每次跑都是全新 session，不再受历史 context 膨胀影响
- **验证**：手动补跑成功，glm-5.2 / 135 秒 / isolated session，正常交付
- 小胡确认方案：选 isolated（方案 1）
