## 宝洁9月数据拉取 — 重复行排查与修复

### 问题
`campaign_export_202609.xlsx` 有203,946行，其中101,873个spot_id几乎都有两行。

### 根因
ADM API `basic/show` 接口 `by_region` 默认 `level0`，同时返回 Global（`region_id=000000000000000000000000`）和 Mainland（`region_id=000000000000000000000008`）两条记录。脚本遍历 `sep_items` 直接append，没有按 region_id 过滤，导致每个点位出两行。

### 踩坑点
1. **region_id 含义**：`000000000000000000000000`（24位0）= Global（全球），`000000000000000000000008` = Mainland（中国大陆）。不是"全国 vs 某省份"。ADM地域码是24位，TVM是10位
2. **API默认行为**：`basic/show` 不传 `by_region` 时默认 level0，返回全球+中国大陆两条。要在客户端按 region_id 过滤

### 修复
脚本 `get_cumulative()` 函数加过滤：只保留 `region_id == '000000000000000000000008'`（中国大陆）的记录。修复后101,873行，0重复

### 关键参数
- API: `https://api.cn.miaozhen.com/admonitor/v1/reports/basic/show`
- platform=pm（PM端/PMP/OTV）
- metrics=acc（累计）
- 脚本路径: `/tmp/export_all_v3.py`
- 数据文件: `/tmp/campaign_export_202609_v2.xlsx`

## Octo 发文件方法

1. **上传文件**：`octo-cli file upload --file <path> --bot-id guguhyx_bot`，返回 CDN URL
2. **发送文件消息**：POST `https://im.deepminer.com.cn/api/v1/bot/sendMessage`，Authorization: `Bearer {botToken}`（从 openclaw.json channels.octo.accounts.guguhyx_bot.botToken 获取），body: `{"channel_id": "d6455e7407db42d5b49a3b975684c910", "channel_type": 1, "payload": {"type": 8, "url": "<CDN URL>", "name": "filename.xlsx", "size": <bytes>}}`
3. **限制**：直接 multipart 上传有 413 大小限制（~1MB），用 `octo-cli file upload` 走 presigned URL 可传大文件
