## 🦞开会群建立 & 分工确定

小胡建了一个 Octo 群「🦞开会」，成员：小胡、octic（小胡的octic）、古古。用于开会协作。

### 最终工作流（小胡确认）
1. octic 会后处理完 → 转写/纪要/待办落盘到在线文档（飞书）
2. octic 群里 @古古，给文档链接
3. 古古读原文核实 → 结合项目认知纠正 octic 可能弄错的人物/项目名/决策方向
4. 古古更新到对应项目文件

关键点：不依赖本地文件互访，用在线文档作为信息传递媒介

### 踩坑
- 被问"群名是什么"时直接报了 inbound context 里的 `group_subject`（原始群ID），没去查真实群名。octic 是主动调 `octo_management` 的 group-info 接口查的。
- 根因：Octo 插件 inbound.js 里 `GroupSubject` 直接赋的是 `message.channel_id`，没解析群名。这是插件层面的 bug。
- 教训：被问到群信息时，主动调 Octo Bot API `GET /v1/bot/groups/:group_no` 查真实群名，不依赖 inbound context
