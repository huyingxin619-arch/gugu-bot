**会议性质：** 内部技术对齐，敲定抽样方案细节后跟Darin过
**Speaker映射：** speaker1=思源、speaker2=丰泽、speaker3=小胡（3人）

### 抽样机制确认
- 在挑战因子接口最上层加"制闪"（采样）动作
- 命中（≤2000/10000=20%）：正常返回挑战因子+像素上报
- 未命中：返回simple_force标记，媒体不执行
- 判定输入：KP + Creative ID + Session ID + 服务器Key → HMAC-SHA256 → 1~10000
- 同一组参数算出来恒定（可复查），大盘随机（参数组合无限多）
- Session ID = MAC + 时间戳 + 素材ID，时间戳变化使不同请求天然不同
- 小胡比喻："你已经知道硬币要落哪一面了"→ 确认单条确定+大盘随机是有意设计

### 随机性确认
- 计算随机的本质：参数算出确定值，但参数组合无限多→大盘分布随机
- 分母=全量请求日志，抽样分布跟请求分布一致
- 媒体作弊风险：理论上可改时间戳反复请求直到命中，但只在补量场景有意义，客户控频可缓解，可做MAC请求频次监控

### 样本量档位
- **5000档：** 保证15秒内每秒分布均匀+抽样代表性，标准差~2-3%（误差1-2%），所需曝光量~25000（20%比例）
- **10000档：** 标准差~1%，精度更高，所需曝光量~50000（~50 CPM）
- 实际值非整齐整数（存在~3.09%波动）
- 小胡建议：对外不说"水位"，统一用"抽样比例"；不暴露3.09等内部计算细节，直接包进5000/10000说明
- 报告频率决定均匀性要求：只看total→整体均匀即可；by day→每天需20000+样本（比例开到50%+）

### 抽样比例调节
- 10~40滑动范围可调（最大可到100），动态加载配置文件，T+1生效
- 当前全局调节，未细化到Creative/Spot ID
- 统计系统先做（看请求次数+抽样是否正确），人工决定次日是否调整，优先级靠后
- 兜底：分母是媒体购买全量，总量不足时调高比例也无效
