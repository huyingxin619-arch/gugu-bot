### ZPSJ 完播率讨论（12:24-13:10）
- 小胡问能否用现有ZPSJ流程计算完播率
- 现有方案：每台设备下发两个取帧时间点（1-1在0-7s，1-2在7-15s），均为随机
- **结论：现有数据结构算不出完播率**
  - 1-2取帧点在7-15s随机，回传了不代表播到末尾
  - 按秒聚合回传率不可读：每秒下发量不均匀（随机分布）+回传缺失率不均匀（技术问题），两个不确定性叠加
  - 能跑通的session里1-1和1-2几乎同时回传（齐全率99.98%），是"绑定"的，连中途断了都看不出
- **方案讨论：额外加末尾取帧点**
  - 0-7s / 7-14s / 14-15s 三个取样点，末尾14-15s回传率=完播率
  - 分母用全部有效session数（没播完=没完播，不管是断了还是技术问题）
  - 14-15s只有1秒窗口，可能没法稳定取到帧
  - 末尾回传还有技术故障风险（SDK/播放器生命周期，小米14s段已证明会锐减）
- **CF下发与曝光的关系待确认**
  - 媒体用creative ID + MAC + 时间戳请求CF服务器
  - 分母可能偏大：CF请求时广告是否已确定曝光？取决于媒体何时请求CF
  - 小胡让人去问了，有update再同步
- 小胡纠正我：没播完和没播到取帧点是一回事，完播率分母本就该包含没播完的。我之前的论证有误。
