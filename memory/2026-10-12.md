## API key 不同步导致 401 全局故障（重要教训）

**事件：** 17:09 小胡发 `/stop` 触发 gateway reload，此后约 27 分钟内所有消息无法回复，401 "无效的令牌"。

**根因：** OpenClaw 的 API key 存在两个位置：
1. `openclaw.json` 里 `models.providers.<id>.apiKey`（provider 级别配置）
2. per-agent SQLite auth profile store（通过 `paste-api-key` 写入）

**优先级：auth profile store > provider config。** 只要 SQLite 里存了 key，gateway 优先用 SQLite 的，不读 openclaw.json 里的。

之前某次更新 API key 时，只改了 openclaw.json（provider config），没有跑 `paste-api-key` 同步到 SQLite。SQLite 里存的还是旧 key（`...EVng`），openclaw.json 里是新 key（`...ZCx66j`）。两个 auth profile 指向同一个旧 key，所以 reload 后全部 401。

**恢复原因：** gateway 收到 SIGTERM 重启，profile 进 cooldown，fallback 到 provider-level 新 key。

**教训：**
- 更新 API key 必须用 `openclaw models auth paste-api-key --provider <provider-id>`，不能手动改 JSON
- `paste-api-key` 会同时更新 SQLite auth profile store 和 config，保证两边一致
- auth profile store 里的 key 不会自动跟随 openclaw.json 更新
- 两个 profile 指向同一个 key 不等于冗余，key 失效就是全挂
- `/stop` 有副作用：触发 config 写入 + gateway reload，不只是停对话

**修复：** 已跑 `paste-api-key` 同步，SQLite 和 config 现在一致。
