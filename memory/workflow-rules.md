# 周报/写作规范

## 周报写作

- **所有进行中的项目都要列**，不能只选"今天提到的"
- **有实质进展的项目**：写清楚做了什么、结论是什么
- **无实质进展的项目**：只列当前状态，一行带过
- **发出前自检三条：**
  1. 无具体人名（包括内部同事名字）
  2. 无具体报价/金额数字
  3. 客户名只有宝洁类 KA 客户需脱敏，三九等其他客户可正常写

## 每日备份前扫描（凌晨3点 cron 执行前）

扫描当日 `memory/YYYY-MM-DD.md`，按内容性质提炼：

| 内容类型 | 动作 |
|----------|------|
| 新的长期事实 | 写入专项文件 + 更新 MEMORY.md 索引 |
| 认知误区/本能校准 | 提炼到 SOUL.md |
| 操作规则 | 提炼到 AGENTS.md |
| 可复用知识 | 提炼到 knowledge/ |
| 具体踩坑 | 留日记，判断是否有普遍性 |

## 梳理/汇报输出标准

当被要求梳理情况、总结事件、列TODO时：

1. **不当压缩器** — 不复述别人已说过的内容，只加增量价值
2. **结构必须完整** — 起因→排查过程→修复结果→遗留问题，不是流水账
3. **每条带细节** — 不只说"plist串配置"，说清楚串到哪、后果是什么、怎么修的
4. **TODO分优先级并给理由** — 🔴高/🟡中/🟢低，每条说明为什么这个优先级
5. **有补充发现** — 在别人说的之外，自己找到新问题或新视角
6. **有自己的判断** — 哪些是真问题、哪些可以后面再说，给出自己的意见

反面案例：2026-07-24，小胡要求梳理当天排查情况，输出只有阿德内容的缩水版复述，无增量信息、无结构、无细节、无优先级。

## 项目 vs 知识分层

- **项目** = 有起止、有负责人、有状态 → `projects/`
- **知识** = 可跨项目复用的原理、架构、术语 → `knowledge/`
