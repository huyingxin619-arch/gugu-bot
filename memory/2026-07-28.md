## PG SDK UA 异常数据分析（深夜讨论）

### 背景
小胡发了 `pc_flagged_9months_hyx.xlsx`（3147条，9个月），和 adm 一起分析"SDK 流量被判 PC"的异常数据。adm 负责 DMS 大盘对比，古古负责行为模式分析。

### 核心发现（交叉验证后）

**device_model 的来源（关键修正）：**
- md 字段：请求中有则保存，没有则解析 UA
- 95.1%（2994条）：请求带了 md 字段 → 伪造者填了移动设备型号（高仿）
- 4.9%（153条）：md 填了空值 → fallback 到 UA 解析 → Windows UA → wDev（低仿）
- **wDev 精确原因**：不是没填 md，是 md 字段值为空 → terran fallback 到 UA 解析 → Windows UA 解不出移动设备 → 返回 wDev
- **wDev 特征**：device_model=wDev，os_type=W，os_version 空，全是同一个 Windows Chrome UA
- **wDev IP 集中**：111.7.100.21~27（北京，7 个连续 IP 段，机房机器）
- **撤回之前的说法**："移动设备型号 + Windows UA 矛盾"不成立，因为 device_model 是请求中 md 字段的值，不是 UA 解析的

**8 条独立证据（修正后）：**
1. ✅ 6 个 OAID 在大盘同时有移动 UA 和 Windows UA（同 ID 双 UA）— 最硬证据
2. ✅ 全零 IDFA 1123 条，IDFV 仅 142 unique，IDFV/CAID/open_udid 严格 1:1 → 142 个虚拟设备身份池
3. ✅ wDev 153 条 + 111.7.100.21-27 连续 IP 段 → 机房机器
4. ✅ fingerprint 527 unique/3147 条，top 指纹 107 次 → 同 IP+UA 反复使用
5. ✅ session 96.2% 单条 → 无真实浏览行为
6. ✅ mzid 全部 unique + uuid_from 100% 是 mzid → 规避去重
7. ✅ 地域 42.6% 集中广东 vs 正常 14.1%
8. ✅ 13.2% mt/smt 负 gap

**伪造链路结论：**
盗用真设备 ID（OAID/IDFV/CAID）→ 构造 SDK 请求 → md 填真设备型号 → UA 填 Windows 浏览器格式 → 批量发监测请求 → 被判为 PC

**全零 IDFA 子群体（35.7%）：**
- 1123 条全是 iOS（os_type=i）
- 142 个 IDFV，每个严格绑定一种 device_model + 1-2 个 IP
- open_udid 和 IDFV 数量一致（142）但值完全不同 → 两套独立标识符
- CAID 129 unique，和 IDFV 严格 1:1
- 大盘正常流量里 0 条全零 IDFA → 只出现在异常流量里

**行为模式异常：**
