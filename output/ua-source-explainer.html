秒针的角色：收数服务器（terran）从 HTTP 请求的 header 中解析 User-Agent。UA 不是秒针采集或生成的，是 HTTP 协议的标准行为——发起请求的客户端自动携带。

解析 UA

UA 来源细节

  • SDK 调用系统网络库发送 HTTP 请求（iOS 用 URLSession，Android 用 OkHttp / HttpURLConnection）
  • SDK 没有显式设置 User-Agent header
  • 系统网络库在发送请求时自动补上默认 UA——这是 HTTP 客户端的标准行为
  • SDK 使用独立网络客户端，不受 APP 自定义 UA 影响

UA 来源细节

  • 监测请求由媒体 APP 自己的代码发起，不是秒针 SDK
  • UA 由媒体 APP 决定：
  • — 如果 APP 主动设置了 UA → 使用 APP 自定义的 UA
  • — 如果 APP 没有设置 → 走 APP 网络库的默认值
  • 不同媒体 APP 的实现可能不同，UA 格式取决于各媒体的开发实践

SDK 监测 vs API 监测：UA 对比

核心差异：谁发起 HTTP 请求
维度 SDK 监测 API 监测
HTTP 请求发起方 秒针 SDK 媒体 APP 自己的代码
UA 由谁决定 系统网络库（URLSession / OkHttp） 媒体 APP
是否主动设置 UA 未设置 取决于媒体 APP 实现
UA 内容 系统网络库默认格式 APP 自定义 或 网络库默认
是否含浏览器标识 通常不含 取决于 APP 是否设置
受 APP 自定义 UA 影响 不受影响（SDK 用独立客户端） 由 APP 自身决定

为什么 SDK 流量会被判成 PC

UA 解析逻辑的 fallback 机制
SDK 流量的 UA
okhttp/4.12.0 等
→
UA 解析引擎
匹配移动端特征
→
匹配不到
无 Mobile / iPhone / Android
→
Fallback: PC
默认判定

原因拆解

  • 平台判断依赖 UA 解析，通过 UA 中的特征标识（如 Mobile、iPhone、Android）识别移动端
  • SDK 流量的 UA 是系统网络库格式（如 okhttp/4.12.0），不含这些标准浏览器移动端标识
  • UA 解析引擎匹配不到移动端特征 → fallback 成 PC
本质：UA 解析体系在设计时面向浏览器流量，浏览器 UA 有标准格式和移动端标识。SDK 监测场景的 UA 来自系统网络库，不在这个体系覆盖范围内。
7

总结

三句话讲清楚 UA 来源
1. UA 是 HTTP 请求的客户端自动携带的，秒针收数服务器（terran）从 header 中解析。谁发起请求，UA 就由谁决定。
2. SDK 监测中，秒针 SDK 调系统网络库发请求，SDK 未主动设置 UA，系统网络库自动注入默认 UA（不含浏览器移动端标识）。
3. API 监测中，媒体 APP 自己的代码发请求，UA 由媒体 APP 决定（自定义或网络库默认值）。
